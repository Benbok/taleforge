# Качество карт — 2026-10-18

[Открыть галерею](index.html) · [Снимок сравнения](preview.png)

Галерея содержит три сравнения с состоянием непосредственно перед этой доработкой
и все 12 актуальных карт. Переключатель показывает общий план, ключевой участок
или иллюстративный вид игрока. Карты открываются отдельно в SVG; для многоуровневых
мест доступны планы этажей. Исходные JSON и SVG первых трёх карт сохранены в `before/`.

## Планировка

| Место | Изменения |
|---|---|
| Придорожная таверна | Зал 12×10, Г-образная стойка, две группы столов со скамьями, очаг и центральные проходы; спальные места и сундуки в отдельной комнате 7×8. |
| Пещера с озером | Грот 14×12, три раздельных скальных островка, проходы вокруг препятствий и смещённые природные детали. |
| Грузовой порт | Причал 4×10 с водой по обе стороны, рабочее место крана; склад 10×8 с проходами между штабелями и стеллажами. |

Глубокая перепланировка этого этапа охватывает эти три места. Остальные девять
сохраняют своё устройство и получили уточнённое визуальное наполнение.
Используются существующие формы и детерминированная маска пещеры; алгоритм формы
сохранённых blueprint не менялся. Криволинейные дороги и произвольный береговой
рельеф в пространственный контракт этим этапом не добавлены.

Все пять seed `1, 7, 42, 99, 123` проходят сборку. Для трёх эталонов проверено,
что provider сохраняет авторские группы деталей без сдвигов, которые разрушили бы
расстановку мебели или пути между скалами. Проверки геометрии также контролируют
доступность выходов, движение, сериализацию и ограничения мандата.

## Наполнение и отрисовка

У всех авторских деталей 12 шаблонов заданы явные `visual_key`. Каталог из 25 видов
различает столы, скамьи, кровати, стойки, стеллажи, бочки, ящики, сундуки, очаги,
факелы, алтари, колонны, камни, обломки, деревья, кусты, камыш, кристаллы, кости,
сети, краны, кнехты, природное свечение, мох и звериные лежки.

Силуэт следует объединению занятых клеток: у Г-образной стойки не закрашивается
пустой угол, у кольцевой детали остаётся отверстие, несвязанные части рисуются
раздельно. Иконка сущности или опасности всегда находится на занятой клетке.
Для растений, валунов и природного свечения нет квадратных подложек.

Материалы различаются рисунком: доски и стыки дерева, плиты помещений, грубая
пещерная порода, трава, земля, волны воды и настил мостов. Тактическая сетка остаётся
отдельным слоем. Тени и рисунки не добавляют клеток, добычи или боевых бонусов.

Явные ключи проходят через `DetailIntent`, `Detail`, JSON blueprint и эскиз. Старые
данные без ключа и неизвестные будущие ключи используют базовый рисунок категории.
Рисунок не выбирается по локализованному имени, ID места или произвольному URL.

Версии рабочего каталога повышены: у трёх эталонов до `1.2.0`, у остальных до
`1.1.0`; соответствия `part_bindings` сохранены. Уже сохранённые планы кампаний
не пересоздаются автоматически; новые версии используются при новой генерации.
Общий рендерер применяется и к ранее сохранённым картам, но у старых деталей
может отсутствовать уточняющий ключ рисунка.

## Техническая модель

`submit_layout` теперь предлагает необязательный `details[].visual_key` из того
же набора рисунков. Новых `maxItems` поверх вложенных массивов нет; исправление
Gemini 400 сохранено. Промпт отдельно различает огонь и природное свечение,
кровать и звериную лежку.

Живой контроль на `gemini/gemini-3.5-flash-lite`: пять мандатов (храм с привязками
и без, таверна, пещера, порт), `seed=7`. **5/5 приняты с первого вызова**, стоимость
`$0.0150957`; ошибки схемы 400 не было. Временный API 500 штатно повторён клиентом.
Это небольшая проверочная выборка, а не гарантия всех будущих ответов.
Все 34 предложенные в этой серии детали получили явный ключ рисунка.
Полные результаты: [model-artwork.json](model-artwork.json).

## Проверки

- 284 профильных backend-теста: детали, геометрия, качество, оба каталога,
  сериализация, приватность и фаза модели.
- 250 frontend-тестов, включая соответствие всех рабочих шаблонов каталогу рисунков.
- TypeScript и `npm run build`: успешно.
- Все 12 шаблонов собраны и перерисованы настоящим `LocationMapSvg` через React SSR.
- Три итоговые карты и галерея просмотрены в Chrome.
- Ruff, форматирование изменённых Python-файлов и `git diff --check`: успешно;
  граф обновлён командой `graphify update .` без вызова модели.
- Независимая проверка кода завершена; найденный случай исчезновения иконки
  в пустом центре детали исправлен и покрыт регрессионным тестом.

В сборке остаются предупреждения Vite о размере общего bundle и существующем
смешении статического/динамического импорта `api.ts`. Полный backend-набор здесь
повторно не запускался: предыдущий общий прогон и его 10 отказов описаны в
[отчёте исправления location_layout](../../location-layout-model/README.md).

## Воспроизведение

Из корня проекта:

```powershell
uv run python experiments/location-layout-templates/scripts/build_templates.py
```

Из `web/`:

```powershell
node scripts/export-experiment-previews.mjs
node scripts/export-map-quality-gallery.mjs
npm test
npm run build
```

Чтобы заново проверить схему живым вызовом (с настроенным `.env`, вызовы тарифицируются):

```powershell
$env:PYTHONPATH = '.'
uv run python experiments/location-layout-model/benchmark.py --runs 1 --output experiments/location-layout-templates/quality-v2/model-artwork.json
```
