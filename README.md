# TaleForge

Текстовая ролевая игра с ИИ-мастером и универсальными правилами. Автор задаёт мир и его законы, игрок описывает героя и действия. Сервер считает броски, ресурсы и последствия; мастер развивает обстановку и рассказывает о сохранённых результатах.

## Возможности

- Пространство автора: черновик мира, проверка, сохранённая версия и независимые прохождения.
- Герои: создание из описания на первом уровне, перестановка стартовых характеристик, редактирование через чат, снаряжение и портрет.
- Игра: небоевые действия и магия, временные эффекты, созданные предметы, бой, броня и расходники.
- Развитие: XP, одинаковые награды участникам, два очка за уровень и присоединение к уровню группы. Библиотечный оригинал не меняется.
- Мир: сохранённые локации, NPC, существа, проходы, знания и приблизительная карта. Клик по карте не выполняет игровое действие.

Интерпретация свободной речи и баланс требуют игрового тестирования с выбранной моделью. Подставные ответы модели проверяют серверные контракты и сохранность, но не качество живого рассказа.

## Установка

Нужны Python 3.11+, Node.js/npm и SQLite либо PostgreSQL. Выполняйте команды из корня нужной рабочей копии.

```sh
python -m venv .venv
```

Активируйте окружение: `.venv/Scripts/Activate.ps1` в PowerShell либо `source .venv/bin/activate` в bash.

```sh
python -m pip install -e ".[dev]"
npm --prefix web ci
```

Скопируйте `.env.example` в `.env`. Укажите `DATABASE_URL`, `SUPERADMIN_NAME`, `SUPERADMIN_PASSWORD` и постоянный `JWT_SECRET`. Ключи провайдеров остаются на сервере. Для Gemini используются `GEMINI_MAIN_MODEL` и `GEMINI_TECHNICAL_MODEL`, для портретов — `PORTRAIT_MODEL`. Примеры находятся в [.env.example](.env.example).

Для новой установки используйте отдельную пустую базу. Пример SQLite: `DATABASE_URL=sqlite+aiosqlite:///./taleforge-universal.db`.

```sh
python -m alembic upgrade head
python -m app.contract
npm --prefix web run gen:api
npm --prefix web run build
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Откройте `http://localhost:8000`. Администратор создаётся из настроек окружения. Для разработки клиента доступна команда `npm --prefix web run dev`.

## Обновление существующей игры

Сохраните резервную копию базы и медиа, установите обновлённые зависимости, остановите приложение и выполните `python -m alembic upgrade head` для прежнего `DATABASE_URL`. Пересоберите клиент и запустите сервер. Не удаляйте базу, тома, медиа или цепочку миграций для обновления универсальных кампаний.

Чистая установка и обновление — разные сценарии. Приложение отклоняет несовместимую старую базу до начальных записей; её преобразование в универсальную систему не поддерживается. Для неё нужен другой адрес новой базы. Пример Docker Compose находится в [docker-compose.yml](docker-compose.yml); проверяйте рабочую копию и тома перед запуском.

## Первый сценарий

1. В библиотеке создайте героя из описания, проверьте характеристики, оружие, броню и портрет.
2. В пространстве автора опишите мир, законы и начало приключения, пройдите проверку и сохраните версию.
3. Игра начинается только из вкладки «Миры»: там все опубликованные миры всех авторов. «Запустить» создаёт новую сессию мира и открывает её кабинет, где администратор настраивает всё нужное; сама сессия стартует после этого. Секреты автора видит только он сам, поэтому за столом чужого мира мастер — ИИ. Добавьте независимую копию героя. Повышение до уровня группы происходит отдельно от создания на первом уровне.
4. Начните сессию и опишите действие в чате. Осмотр карты сам по себе не расходует время.
5. При ошибке используйте повтор исходной реплики. Сохранённая квитанция не перебрасывает кубики и не списывает ресурсы повторно.

Подготовка нового места может обращаться к модели. Портрет создаётся отдельной кнопкой. Расходы зависят от выбранного провайдера и настроек кампании.

## Проверки

Обычные тесты блокируют живые вызовы модели. PostgreSQL для тестов настраивается переменной `TEST_DATABASE_URL`; никогда не используйте рабочую базу: тестовые фикстуры очищают свои схемы.

```sh
python -m pytest -n auto
python -m ruff check app tests tools
python -m ruff format --check app tests tools
python -m app.contract --check
npm --prefix web run typecheck
npm --prefix web test
npm --prefix web run build
```

Установка и обновление проверяются в `tests/test_universal_boot.py` и `tests/test_universal_upgrade.py` через миграции и запуск приложения. Сквозное прохождение и повтор действий — в `tests/test_universal_playthrough.py`. Аудит удаления старого движка — в `tests/test_universal_legacy_audit.py`.

## Устройство проекта

`app/rules/universal` содержит числовые контракты, `app/core/universal` — сохранение и игровые операции, `app/agents/master` — работу мастера. REST находится в `app/api`, доставка событий — в `app/gateway`, клиент — в `web`. Схема изменяется миграциями в `alembic/versions`.
