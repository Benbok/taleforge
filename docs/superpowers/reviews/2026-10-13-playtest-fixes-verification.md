| 11 | Обычный и потоковый ответы сохраняют `finish_reason` и признаки блокировки. Пустое повествование отмечается в `LlmCall.error`, повторяется один раз и заменяется фактическим ответом. |
| 12 | Поиск требует новых знаний/факта для нужного героя и цели либо находки с `discovery_check_event_id`. Повторное раскрытие уже известных сведений не считается результатом. Незавершённый поиск возвращается мастеру; после бюджета явно отменяется. |
| 13 | Рассказчик обязан использовать зарегистрированные значимые предметы; неизвестная предметная разметка блокируется. Произвольная проза о выдуманном предмете не распознаётся семантически: это ограничение промптной защиты. |
| 14 | Подсказка адаптации получает допустимые `key`, `namespace`, `kind`, `temporal_semantics`, `freedom` непосредственно из Literal контрактов. |

| 16 | Эффекты заклинаний сохраняют id источника. Очарованный не выбирает источник для автоматической атаки, включая ближайшую цель на сетке; ручная атака, захват, толчок и вредное целевое заклинание также отклоняются. Другие цели остаются допустимыми. |
| 17 | Заклинание с одним эффектом `charmed` без урона не запускает бой автоматически только из-за спасброска. Подсказка отличает враждебность от обнаружения героя. Постоянное отношение не переписывается: защита источника действует пока существует эффект. Это не гарантия незаметного сотворения. |
| 18 | В описание `advance_plot` добавлена проверка достигнутой цели по применённым результатам, а не по входу в комнату/намерению. Это минимальная промптная защита; семантического серверного доказательства достижения произвольной цели нет. |
| 19 | Ошибки квоты отделены от обычного сбоя хода. Для spending cap игрок получает объяснение бюджета и инструкцию владельцу проверить расходы проекта. Клиент блокирует сетевые вызовы провайдера до рестарта после восстановления бюджета; временная квота имеет паузу 60 с. Режиссёр проверяет блокировку до захвата задания, сводки пропускаются. |
| 20 | Ранее внесённое исправление реестра повествования учитывает существующие названия и id инвентаря. `inv_id` сохраняет имя обычным текстом без неработающей ссылки. Причина в описанном примере — неизвестный id инвентаря: `rejected_names` собирался из неизвестных ссылок повествования, а не непосредственно из отказов инструментов. |
