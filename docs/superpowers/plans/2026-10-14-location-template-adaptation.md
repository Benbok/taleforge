# Адаптация шаблонов к автоматически созданным кампаниям

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Использовать качественные части шаблонов в локациях с произвольными именами, дополнительными зонами и другим входом, сохраняя требования сюжета.

**Architecture:** Сохранить существующее точное сопоставление для уже совместимых планов. При его отказе построить структуру из мандата и перенести оформление однозначно сопоставленных частей шаблона; дополнительные зоны оформить детерминированными пресетами. Провайдер проверяет итоговую геометрию до сохранения snapshot.

**Tech Stack:** Python, Pydantic, существующий DeterministicLayoutProvider, pytest; без новых зависимостей и дополнительных вызовов LLM.

**Spec:** `docs/superpowers/specs/2026-10-14-location-template-integration-design.md`; дополнение — согласованный в разговоре подход: роли, дополнительные части, диагностика отказа модели, качество запасной генерации.

## Global Constraints

- Работа непосредственно в существующей рабочей копии main `.tmp/main-push`.
- Сохранённые карты и резервы не пересоздавать автоматически; боевую кампанию использовать только для чтения.
- Сохранять ref, entry, required, secret, below, явные shape/material, подходы и все сюжетные anchors/residents.
- Snapshot остаётся самостоятельным: повторная генерация не перечитывает изменившийся каталог.
- При неоднозначном сопоставлении не угадывать роль; дополнительная зона остаётся частью мандата.
- Итог ограничен действующими лимитами LayoutIntent и провайдера; не ослаблять obligations ради выбора шаблона.

## Review Focus

1. Произвольные русские названия и английские ref не должны блокировать однозначное сопоставление.
2. Другой вход не должен переносить персонажа в набережную вместо причала.
3. Тайник не раскрывается, обязательный склад достижим открытым путём.
4. Перенос solid-деталей не перекрывает подходы и переходы.
5. Старый snapshot и уже готовая карта сохраняют прежний результат.

## Файлы и интерфейсы

- Новый `app/core/layout/template_roles.py`: `infer_role(ref: str, name: str, purpose: str) -> str | None`, ограниченный словарь ролей и русских/английских синонимов. Не считать произвольное слово достаточным доказательством роли.
- Новый `app/core/layout/template_adaptation.py`: `adapt_parts(template: LayoutTemplate, mandate: Mandate) -> tuple[LayoutIntent, dict[str, str]]`.
- `app/core/layout/template_selection.py`: точное сопоставление, затем адаптация частей, затем проверка provider; ранжирование по покрытию и стабильному seed.
- Новый `app/core/layout/scenery.py`: `enrich_intent(intent: LayoutIntent, mandate: Mandate) -> LayoutIntent`, детерминированное оформление известных ролей.
- `app/core/layout/executor.py`, `app/agents/layout_model.py`: безопасная диагностика действительных причин отказа.
- Новые tests/fixtures/greihall-layout-mandate.json и тесты адаптации; существующие тесты интеграции и каталога.
