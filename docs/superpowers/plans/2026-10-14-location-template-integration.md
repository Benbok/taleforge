# Location Template Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Автоматически применять совместимые проверенные шаблоны к локациям новых кампаний, сохраняя мандат и существующий резервный путь.

**Architecture:** Версионированный каталог загружается отдельно от контентных пакетов. Чистый подбор и адаптер фиксируют готовый intent в reservation; исполнитель сначала пробует снимок и при отказе продолжает существующую генерацию. Модель не вызывается для выбора или адаптации шаблона в первой поставке.

**Tech Stack:** Python, Pydantic, SQLAlchemy, pytest; существующие LayoutIntent, Mandate, provider и world_generation.

**Spec:** `docs/superpowers/specs/2026-10-14-location-template-integration-design.md`.

**Execution:** Реализовано в main 2026-10-14. Задания 1–5 завершены;
проверки и уточнения находятся в `docs/superpowers/reviews/2026-10-14-location-template-integration.md`.
Полный layout-прогон ограничен воспроизводимым baseline WebSocket-таймаутом;
целевые backend/frontend проверки прошли. Перечень ниже сохранён как исходный план.

## Правила исполнения

Работать в отдельной ветке от актуального main. Текущая коллекция сохранена коммитом f7d0c39 в feat/multipart-actions: проверить её наличие в базе перед началом; если отсутствует, перенести этот отдельный коммит, не сливать всю ветку с посторонними изменениями. Сохранить незакоммиченные изменения пользователя. После каждого задания выполнять указанные проверки и отдельный коммит. Никаких сетевых вызовов в тестах.

## Файлы и ответственность

- `app/core/layout/template_catalog.py`: схема записи, загрузка, версия и checksum.
- `app/core/layout/template_selection.py`: кандидаты, совместимость, явное сопоставление и адаптация intent.
- `app/content/layout_templates/*.json`: 12 принятых записей; отдельно от загрузчика пакетов content.
- `app/core/layout/plan.py`: получение template_id/tags из каталога места.
- `app/core/layout/store.py`: снимок выбора при первом резервировании.
- `app/core/layout/executor.py`: применение снимка перед моделью и диагностика источника.
- `app/core/campaigns.py`: default нового флага.
- `tests/test_layout_template_catalog.py`, `tests/test_layout_template_selection.py`, `tests/test_layout_template_integration.py`: контракты, подбор, транзакционный pipeline.
- `docs/map-generation-quality.md`: поведение и ограничения.

- [ ] Реализовать `load_catalog(path: Path | None = None) -> tuple[LayoutTemplate, ...]`. Возвращать отсортированные валидные записи, логировать отклонённые записи без содержимого секретов. Не использовать импорт экспериментальных фабрик.
- [ ] checksum вычислять SHA-256 от канонического JSON записи без checksum: UTF-8, sort_keys=True, компактные separators. Хранить checksum при резервировании; неизвестную schema version отклонять.
- [ ] Перенести intent 12 шаблонов из experiments. Мета-информация для runtime — явная, не копировать отзывы, сценарии NPC или данные кампаний. Запретить anchors и outside_id в исходнике каталога.
- [ ] Проверить все runtime intent на пяти seed существующим provider и geometry; повторить тесты каталога и сделать коммит.

## Задание 2. Совместимость и адаптация

- [ ] Написать тесты: подходящий default таверны, отсутствующий тип, неоднозначность, outdoor/indoor, материал, shape, нижний уровень, secret, required, лишние секреты, коллизии ref, якоря и жители.
- [ ] Создать `TemplateContext(template_id, tags)` и `select_template(mandate, context, seed, catalog) -> TemplateSnapshot | None`; причины отказа вернуть отдельным результатом диагностики. Не распознавать тип или роль по тексту name/purpose.
- [ ] Определить явные bindings для стандартных spatial refs `main`, `part_1`, `part_2` отдельно по template_id. Например таверна: main→taproom, part_1→private_parlor, part_2→cold_cellar; secret_vault допускается только при явном секретном мандате, иначе этот вариант отклоняется. Проверить соответствие назначения каждой части; нельзя называть кабинет спальней ради совпадения.
- [ ] Для авторского spatial принимать только объявленные ref aliases с однозначным соответствием. Не добавлять эвристику по индексу для неизвестных refs. Не требовать, чтобы все 12 шаблонов обязательно применялись: несовместимость означает нормальный fallback.
- [ ] Отфильтровать кандидаты по template_id или явному тегу архетипа, затем окружению и обязательствам. Стабильно ранжировать SHA-256 от seed/id/version, выбирать первый совместимый из максимум трёх кандидатов. Не использовать Python hash().
- [ ] В `adapt_template(template, mandate, bindings) -> LayoutIntent` глубоко копировать данные, переписать entry, part_ref, connects_to и связанные ссылки. Дополнительные части получают свободные refs без коллизий; limit MAX_AREAS сохраняется.
- [ ] Названия, назначение, environment, secret, required, явно заданные shape/material брать из мандата, но несовместимый исходный вариант сначала отвергать. Размеры, детали и геометрические связи сохранять.
- [ ] Подходы получать из мандата и совместимых сторон шаблона. При нехватке сторон или конфликте полос не изменять требования мандата — отклонить кандидат. outside_id всегда None.
- [ ] Жителей и якоря распределить так же, как существующий детерминированный кандидат `spatial.intent_candidates(mandate)[0]`, с переписанными refs. Проверить ровно одну привязку каждого holder.
- [ ] Перед принятием вызвать obligations и provider.propose с реальным seed; геометрию проверить через валидатор provider. Чистые функции не обращаются к БД или модели.
- [ ] Запустить тесты selection/catalog и существующие tests/test_layout_quality.py; сделать коммит.

## Задание 3. Снимок выбора в резерве

- [ ] Создать тесты повторного резервирования, обновления каталога после резерва, старого резерва без полей и выключенного флага.
- [ ] Добавить `location_layout_templates=True` только в настройки новых кампаний. Проверка отсутствующего значения у существующих кампаний должна возвращать False. Не менять другие defaults.
- [ ] В `plan.reserve_from_plan` разрешить template_id и теги через world.catalog; передать `TemplateContext` в store новым необязательным keyword аргументом. Существующие вызовы store остаются рабочими.
- [ ] В `store.reserve_plan_layout` после получения seed и до записи reservation выбрать шаблон. Проверка существующего row остаётся первой: повтор не делает новый выбор.
- [ ] reservation дополнить `template_selection`: schema_version, id, version, checksum, bindings, полный adapted intent, outcome/reason. При отсутствии кандидата также зафиксировать outcome, чтобы повтор не перечитывал новый каталог. Положительный snapshot должен быть полностью автономным.
- [ ] Не менять Mandate и не вводить SQL-миграцию: снимок помещается в существующий JSON reservation. Не удалять source=plan и generator_version.
- [ ] Проверить module/manual/уже построенные места через существующий eligible; выполнить новые тесты и tests/test_layout_plan_phase.py, сделать коммит.

## Задание 4. Исполнитель и резервный путь

- [ ] Написать интеграционные тесты: snapshot успех без LLM; snapshot повреждён/несовместим → прежняя модель; модель выключена → прежний deterministic; spend limit не мешает шаблону; старый reservation использует старое поведение.
- [ ] В executor._draft после загрузки и валидации Mandate, перед _ask_model, разобрать snapshot, проверить obligations и provider.propose. Не перечитывать runtime-каталог.
- [ ] При успехе использовать существующие _with_anchors и _publish_layout; сохранить source=template и id/version во внутреннем результате фазы. Модель, её бюджет и LlmCall не вызываются.
- [ ] При ValidationError/LayoutError снимка записать короткую причину template fallback и продолжить прежний путь. Не перехватывать ошибки БД/инфраструктуры как несовместимость шаблона.
- [ ] Отделить диагностику источника от notes, влияющих на quality: отказ шаблона сам по себе не делает успешный модельный результат fallback. Наименьшее изменение интерфейса _draft — отдельный объект диагностики, который передаётся в публикацию.
- [ ] Проверить идемпотентность публикации, перенос NPC и привязок, сохранение ручной геометрии и опубликованного blueprint.
- [ ] Запустить tests/test_layout_template_integration.py tests/test_layout_plan_phase.py tests/test_layout_model_phase.py tests/test_layout_geometry.py; сделать коммит.

## Результат поставки

Рабочий каталог и автоматическое применение совместимых заготовок в новых автономных кампаниях; старые кампании и резервы сохраняют прежнее поведение; неизвестные или несовместимые места продолжают существующую генерацию. Ограниченная модельная адаптация и расширение коллекции — последующие задачи на основании измеренной доли попаданий.
