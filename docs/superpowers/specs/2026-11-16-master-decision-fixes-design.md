# Мастер universal: исправление ошибок разбора и бюджетов попыток (задача 1 из 3)

## Зачем

Ход в universal разбирает модель (`exploration_decide`), затем проверка смысла (`intent_review`) и проверка рассказа (`narration_review`). Несколько ошибок в этом пути роняют ход или ухудшают разбор без всякой причины в игре. Эта задача убирает их, не меняя устройства игры. Задачи 2 (правило броска, `free_effect`, запасной путь, повтор попыток) и 3 (ход мира: NPC, враги, секреты, факты) идут отдельно.

## Цели

1. **Температура структурных вызовов.** Все структурные цели (`decide`, `exploration_decide`, `intent_review`, `narration_review`, `world_prepare`, `world_review`) идут на 0.2 независимо от `cfg.temperature`. Сейчас 0.2 стоит только у `decide` (`app/agents/master/universal.py`, `_call`). Модели без поддержки температуры по-прежнему обрабатывает `supports_temperature`.
2. **Модуль наград включён всегда.** `_rewards` в `app/agents/master/prompting/modules.py` ищет латинское `reward` в русской истории и почти никогда не срабатывает. Новое поведение: модуль включается всегда. Риска нет: `app/core/universal/rewards.py` сам проверяет каждую награду (победа подтверждена уроном и нулём HP, исследование подтверждено наблюдением, квест завершён) и не выдаёт её повторно (`receipt_key`).
3. **Устойчивый разбор ответов проверок.** Голый `json.loads` для `intent_review` и `narration_review` в `app/agents/master/exploration.py` заменяется схемой «`json.loads`, затем `repair_json`, затем проверка схемы».
   - `intent_review` не разобран → считается вердиктом `mismatch` с сообщением о сбое проверки и расходует бюджет смысла (см. п. 5). Автоматического `pass` нет.
   - `narration_review` не разобран → текст принимается (проверка латиницы к этому моменту пройдена), сбой пишется в лог.
4. **Нормализованная сверка цитат.** Цитаты требований (`requirement.quote` против `source`) и `introduction.evidence_quote` против `evidence` в `app/core/universal/interpretation.py` сравниваются после одной общей нормализации: casefold, `ё`→`е`, схлопывание пробелов, приведение кавычек `«»„“”"'` к одному виду. Сохраняемые цитаты не меняются, нормализация нужна только для сравнения.
5. **Раздельные бюджеты попыток** в `obtain_exploration_action`. Вместо общего `proposal_attempts[mid] < 2`:
   - `lore`: 1 дополнительный вызов после запроса лора;
   - `format`: 2 попытки исправить ошибку формата или компиляции (невалидный JSON, ошибка схемы, `ValueError` при компиляции);
   - `meaning`: 1 повторная попытка после вердикта проверки смысла `mismatch` (включая неразобранный ответ проверки);
   - общий потолок: 4 вызова `exploration_decide` на реплику.

   Причину каждой попытки фиксирует код по тому, чем закончилась предыдущая. Счётчики, как и сейчас, сохраняются в trace до внешнего вызова, поэтому упавший вызов не даёт лишней попытки. `proposal_attempts[mid]` остаётся общим числом вызовов, новые счётчики лежат рядом. Старый trace, где есть `proposal_attempts[mid] >= 2`, но нет новых счётчиков, считается исчерпанным по старому правилу: начатый до обновления ход не получает лишних вызовов.

## Не цели

- Навыки во внеигровых проверках (`trained=False` в `exploration_resolution.py`, `investment.py`). В universal навыков нет, `sheet.trained` — это список способностей. Вопрос переносится в задачу 2.
- Запасной путь `fallback_action`, который ставит `pass` и оформляет слова игрока как `free_effect`. Это задача 2.
- Отдельная модель для проверки смысла и запуск проверки по признакам сервера. Это задача 2.
- Правка промпта CORE о броске на любое действие. Это задача 2.

## Анти-цели

- Магия или опасное действие проходят без проверки смысла из-за сбоя проверяющего.
- Один ход стоит больше 4 вызовов разбора.
- Повторная обработка после сбоя (recovery) получает бесплатную попытку.

## Подходы к бюджетам

- **А (выбран):** отдельные счётчики по причине плюс общий потолок. Ошибка в одном месте не съедает попытки другого, цена хода ограничена.
- **Б:** общий бюджет 4. Меньше кода, но лор и формат по-прежнему могут выжечь всё до проверки смысла.

## Проверка

- Юнит-тесты на каждый пункт: температура по цели, включение модуля наград, неразобранный ответ каждой проверки, сверка цитат с `Ё`, регистром и кавычками, раздельные бюджеты (лор не съедает формат, потолок 4, recovery без лишней попытки, старый trace).
- Существующие тесты в `tests/test_exploration_master.py` и соседних проходят.
- По желанию: прогон eval из `tests/eval` до и после.

## Оставлено исполнителю

Имена ключей trace для новых счётчиков, текст сообщения о сбое проверки, место общей функции нормализации.
