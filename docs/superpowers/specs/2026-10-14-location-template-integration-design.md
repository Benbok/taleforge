# Подключение шаблонов локаций к генерации кампаний

Статус: проект для ревью. Реализация не начата.

## Цель

Кампании, которые модель создаёт без участия пользователя, используют проверенные пространственные заготовки для подходящих локаций. Подбор сохраняет описание, обязательные части и сюжетные привязки кампании. При отсутствии совместимой заготовки остаётся существующий путь генерации.

Первая поставка использует 12 экспериментальных шаблонов. Массовое расширение каталога, новые художественные ресурсы, правила плавания и изменение боевых укрытий в неё не входят.

## Исходное состояние

`plan.ensure_spatial()` задаёт spatial, `store.reserve_plan_layout()` сохраняет Mandate, `executor._draft()` сначала запрашивает модель, затем пробует детерминированные кандидаты. `spatial.obligations()` требует сохранения ссылок частей, окружения, тайности, заданных материалов и форм, нижних уровней и привязок. Blueprint строится provider и публикуется одной транзакцией.

Каталог нельзя просто подставить вместо Mandate: ссылки частей и их состав различаются. Совместимость с обязательствами проверяется до публикации, а не по одному имени «таверна».

## Каталог

Промотировать только исходные intent и метаданные в отдельный версионированный каталог ресурсов. Не загружать SVG, отчёты и экспериментальные фабрики в runtime. Каталог не является пакетом location_template существующего контентного загрузчика.

Запись содержит id, version, archetype, совместимые location template_id, environment, масштаб, роли частей, допустимые соответствия частей и LayoutIntent. Поля для подбора явные, проверяются схемой. Изменение содержимого требует новой версии и контрольной суммы. Ошибка одной записи отключает эту запись и оставляет резервный путь; ошибка публикуемого каталога должна выявляться тестами до релиза.

## Подбор

Отдельный чистый модуль выбирает не более трёх кандидатов по template_id и явным тегам. Произвольный текст не разбирается эвристиками по подстрокам. Неизвестный тип места использует существующую генерацию. Модель архитектора может выбирать существующий template_id как сейчас.

Сначала фильтровать по окружению и совместимости обязательных частей. Вход сопоставляется только входу. Каждая часть Mandate получает отдельную часть шаблона; соответствие допускается только по явно объявленным ролям. Форма, материал, тайность и нижний уровень должны совпасть. При неоднозначности кандидат отклоняется; модель не решает неоднозначное соответствие в первой версии.

Дополнительные части допустимы в пределах MAX_AREAS, если они не добавляют неподтверждённых секретов, NPC, добычи или событий. Шаблоны с тайником допустимы только для мандата, который уже предусматривает тайную часть. Идентификаторы, названия и сюжетные привязки мандата имеют приоритет. Не заменять авторский spatial шаблоном ради повышения доли попаданий.

Совместимые варианты ранжируются детерминированно по seed и id. В первой версии не добавлять общий счётчик использования: это усложняет конкурентные резервы. Долю совпадений измерять; она может быть низкой из-за строгой совместимости.

## Резерв и воспроизводимость

Сохранять выбранный шаблон и его версию, контрольную сумму, соответствие ссылок и полный исходный intent в reservation при создании резерва. Повторный запуск использует снимок, даже если каталог изменился. Старые резервы без снимка продолжают существующий путь. Не пересобирать опубликованные карты.

Перед публикацией переписать ссылки parts, connects_to, entry, bands и approaches без коллизий. Привязки распределить по правилам мандата, проверить obligations и provider.propose с реальным seed кампании. Внешние подходы согласовать с мандатом; если это разрушает геометрию, перейти к резервному пути.

## Адаптация моделью

Первый успешный результат — готовый совместимый шаблон, который не требует отдельного layout-вызова модели. Названия и описания частей берутся из мандата. Декорации остаются нейтральными. Это даёт проверяемое сокращение вызовов и сохраняет композицию.

Модельная адаптация координат, размеров и связей откладывается: она лишает заготовку проверенной композиции и усложняет первую поставку. Следующий этап может разрешить ограниченную адаптацию текста и визуальных вариантов после измерения результата.

## Флаги и fallback

Добавить campaign setting location_layout_templates. Для новых кампаний — true, существующие кампании без значения сохраняют прежнее поведение. location_layouts=false отключает весь pipeline. При location_layout_templates=true использовать совместимый снимок первым независимо от location_layouts_llm. Этот флаг управляет модельным резервным путём, а не использованием статических ресурсов.

Если снимка нет, obligations не пройдены или provider отклонил intent, продолжить текущий модельный и детерминированный pipeline. Не создавать дополнительный LLM-вызов для поиска шаблона. Сохранить причину отказа; применение совместимого шаблона — normal, отказ шаблона сам по себе не означает пониженное качество успешно сгенерированной карты.

## Диагностика

Внутренний результат фазы содержит source, template id/version при применении и причину template fallback. Не показывать игроку технические ID. Измерять долю попаданий, причины отказа, длительность layout-фазы и фактическое число LLM-вызовов. Не обещать ускорение всей кампании без измерений.

## Проверки и границы готовности

Проверить загрузку и версии 12 записей, детерминированность, неоднозначные соответствия, несовместимые материалы и окружение, секреты и обязательные части, перенос NPC/сюжетных привязок, отсутствие внешних ID и изменение каталога после резерва.

Интеграционные сценарии: совместимая локация публикует blueprint без LLM-вызова; несовместимая запускает прежний путь; повреждённая запись не блокирует кампанию; ручная карта и опубликованный blueprint сохраняются. Проверить сочетания трёх флагов и настройки старых кампаний.

Критерий готовности: новая автономно созданная кампания может применить шаблон без действий владельца; обязательства сохранены; повторная обработка резерва воспроизводима; fallback рабочий; исходные карты не меняются.

## Следующий артефакт

После ревью этой спецификации — подробный план с файлами каталога, выбора, резервирования и интеграционных тестов. Текущая версия намеренно начинает с детерминированного применения: адаптация моделью будет отдельным расширением после проверки попаданий.
