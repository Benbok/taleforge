# Локальные SFX: оценка спека и принятый дизайн

Цель владельца: мастер может запрашивать локальные короткие эффекты без ожидания inference, сохранять подписанные результаты, повторно использовать их и прослушивать/регенерировать через настройки кампании.

## Аудит

- `app/core/audio.py`, `app/tools/audio.py`: существующие музыкальные треки, cue и MAX_SFX=2 сохраняются. enabled ошибочно требует музыку: исправляем на флаг кампании; выбор музыки остаётся отдельной проверкой.
- `web/src/game/sound.ts`: один Web Audio микшер, авторизованные загрузки, индивидуальная громкость, autoplay unlock и ducking для речи. Новый эффект идёт через этот микшер.
- `app/tools/runtime.py`: publish_changes вызывается после commit и публикации текста. Здесь активируется адресная доставка новых эффектов.
- `app/agents/tts.py`: VoiceStudioTTS вызывает настроенный `/v1/audio/speech`; вычислительное устройство внешнего процесса Taleforge не контролирует. Общий GPU semaphore был бы недостоверным. CPU SFX по умолчанию.
- Существующие RedisBus/MemoryBus доставляют события по seat IDs. Постоянной универсальной очереди для аудио нет; существующий world generation runtime имеет другую семантику и не используется для SFX.
- Scene имеет campaign_id, а не отдельный scene_id. Проверяем location_id, mode, round, game_time, состав/места героев и текущую сессию. Проверка на клиенте дополняет серверную.
- Рабочее дерево до начала содержит изменения adventure.py, master/places.py, test_adventure.py, uv.lock. Их сохраняем.

## Решения

1. SQLAlchemy: подписанный звук с уникальным ключом внутри кампании; immutable версии файлов с параметрами; устойчивое задание с retry/lease и собственным снимком параметров; одноразовая заявка воспроизведения. Общая строка блокировки сериализует короткий admission и обеспечивает максимум один inference между процессами. Игровые задачи сохраняются как staged без глобальной блокировки на время LLM-хода; атомарные upsert и частичный уникальный индекс исключают дубли активных задач. Блокировка не держится во время inference.
2. Ключ: Unicode NFKC, casefold, свёрнутые пробелы описания/контекста + duration + backend/model/revision/device/steps + стабильный seed. Семантическое сходство автоматически не приравнивается: мастер может явно повторить сохранённый sound_id. Это исключает подмену существенно разных звуков.
3. Отдельный дочерний процесс выполняет адаптер Stable Audio 3 и ffmpeg. Библиотека модели не импортируется в FastAPI. CPU threads ограничены; GPU только отдельной конфигурацией окружения разработки. Таймаут убивает дочерний процесс и освобождает ресурс. Compose worker запускается автоматически вместе с приложением, на CPU, с лимитами ресурсов и тем же протоколом БД.
4. Локальные веса и кеш text encoder автоматически готовятся при первом старте worker; во время игры HF offline. Инференс не вызывает внешний сервис. Скачивание весов требует учётной записи владельца и принятия условий; приложение стартует независимо от подготовки модели.
5. WAV проверяется и ограничивается 1–4 сек., PCM, 1–2 канала, размером и амплитудой; ffmpeg создаёт OGG/Opus с ограниченной громкостью. Только серверные ID, атомарная запись; метаданные публикуются после файла. Квота не удаляет сохранённые пользовательские результаты молча.
6. request_sfx максимум один за ход, резервирует один из двух слотов вместе с play_sfx и автоcue. В очередь записывается внутри транзакции; rollback не оставляет задач. Доставка активируется после публикации хода; перезапуск не воспроизводит старые эффекты.
7. audio.sfx_ready содержит event_id/request_id, track, now/expires_at и место. Адресаты фиксируются по текущей группе; перед доставкой сверяем актуальность и отключение. Режим/раунд события учитывают персональную проекцию мирной группы при бое в другом месте. Клиент проверяет срок, место, дедупликацию и состояние микшера повторно после загрузки.
8. Настройки кампании: включение генерации отдельно от audio_enabled; сохранённые названия/описания, ручная генерация, прослушивание текущей/прошлых версий, регенерация с новым seed, закрепление, удаление. Старый результат остаётся доступным при ошибке замены. Прослушивание настроек не рассылает звук игрокам.
9. Доступ к списку и файлам — участники/владелец кампании; управление — только владелец. Администратор видит общую очередь/ошибки/статистику без публичной раздачи файлов.

## Границы проверки

Автотесты используют управляемый renderer, реальные CPU WAV/OGG fixtures при доступном ffmpeg. Не обещаем benchmark модели без скачанных весов, принятой лицензии и теста одновременно с реальными LLM/Voice Studio/STT. Отдельная инструкция и benchmark команда входят в поставку.
