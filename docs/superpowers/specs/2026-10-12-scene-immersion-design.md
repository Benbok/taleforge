# Погружение: шапка локации, освещение сцены и хроника

Дата: 2026-10-12. Статус: проект решения для плана реализации; продуктовый код ещё не меняется.

## 1. Цель и принятые решения

Игрок быстрее узнаёт место действия, чувствует его атмосферу и читает события
как совместную историю. Пользователь выбрал три изменения: шапку локации,
освещение сцены и оформление хроники. Для изображений выбран вариант
«Готовые иллюстрации и SVG-композиции».

Это единый проект игрового экрана с тремя последовательно принимаемыми
поставками. Данные оформления общие для шапки и света; хроника добавляется
после них. Генерация растровых изображений и новые платные сервисы не нужны.

**Карты исключены из проекта по прямому указанию пользователя.** Не менять
`docs/superpowers/plans/2026-10-12-location-maps-delivery1.md`, спецификацию
генеративных карт, компоненты карты, её API, геометрию, раскрытие, построители
и подготовку локаций. Этот проект не ждёт готовности разработки карт.

## 2. Текущие точки интеграции

| Область | Текущее устройство | Изменение |
|---|---|---|
| Сцена | `Scene.location` содержит ID и имя | Отдельное необязательное `Scene.presentation` |
| Проекция зрителя | `visible_scene` → `scene_payload`, одинаково для snapshot и updates | Оформление только выбранной текущей локации |
| Тема | `lib/theme.ts` задаёт токены пакета на `:root` | Декоративные переменные только внутри `GamePage` |
| Сообщения | `Message.data`, `message_payload`, поток `message.chunk` | Сохранённый контекст места и явная область сообщения |
| Лента | `ChatFeed`, `MessageView`, `RichText` | Заголовки мест, книжная типографика, компактные игровые реплики |
| Отряд разделён | `visible_to` ограничивает доставку; `whisper` также true у сообщений группы | Различать оформление группы и личного шёпота, сохранив доставку |

Новые данные не берутся из `CampaignSecret`, скрытого каркаса, соседних мест,
карты, музыки или системных часов компьютера. Погода и период суток
показываются только при явном публичном указании мастера.

## 3. Оформление локации

Хранить необязательный объект `Entity.state.presentation` у текущей локации:

```text
LocationPresentation:
  preset: neutral | tavern | coast | forest | ruins | crypt | sanctuary
  period: dawn | day | dusk | night | null
  weather: clear | cloudy | rain | fog | snow | null
  illustration_key: строковый ключ до 64 символов или null
```

Поля периода, погоды и изображения по умолчанию null; preset — neutral.
Ключ изображения допускает только `[a-z0-9_-]`, не URL и не путь к файлу.
Клиент принимает изображения только из собственного статического каталога.
Неизвестный ключ означает SVG выбранного preset, а не внешний запрос.

При отсутствии `state.presentation` допустим декоративный выбор preset из
уже публичного имени места. Использовать только явные слова: «таверна»/
«трактир»/«tavern»/«inn» → tavern; «бухта»/«берег»/«порт»/«coast»/«harbor» →
coast; «лес»/«forest» → forest; «руины»/«ruins» → ruins; «склеп»/«крипта»/
«катакомбы»/«crypt»/«catacombs» → crypt; «храм»/«святилище»/«temple»/
«sanctuary» → sanctuary. Слова проверять отдельно, без поиска произвольных
подстрок. При нескольких совпадениях приоритет: crypt, sanctuary, tavern,
coast, forest, ruins. Это художественный мотив, а не новый факт о мире.
Период суток и погоду из имени или описания не извлекать.

Для изменения оформления добавить отдельный журналируемый инструмент
`set_location_presentation(location_id, preset, period, weather, illustration_key)`.
Он полностью заменяет только `state.presentation`, сохраняет остальные
ключи состояния и имеет обратную дельту. Работает через существующие права
и UI инструментов мастера. Создание, переходы, develop и подготовку локаций
не менять. Без вызова инструмента шапка уже работает с запасным оформлением.

## 4. Шапка

Разместить `LocationHeader` внутри центральной колонки перед `CombatStrip`.
Название места — кнопка существующей карточки знаний. Дополнительная строка
содержит известные период и погоду: «Сумерки · Туман». Неизвестные поля
пропускаются. При отсутствии места текст — «Место ещё не названо», рисунок
нейтральный, кнопка карточки отсутствует.

Высота: 132 px на экране шириной от 768 px, 72 px на телефоне; в бою 72 px и
48 px соответственно. В кнопке «Свернуть шапку» пользователь может оставить
только строку высотой 48 px. Выбор сохраняется в браузере. Длинное имя
переносится максимум на две строки; полный текст доступен в имени кнопки.

Первая поставка содержит семь готовых локальных SVG-иллюстраций — по одной
для каждого preset. Каталог поддерживает локальные WebP/AVIF и указание
фокусной точки, когда подходящая готовая иллюстрация будет добавлена.
Наличие растра не является условием работоспособности. Изображение
декоративное (`alt=""`); осмысленная информация находится в тексте.

Таверна — янтарный свет и силуэты балок, берег — горизонт и холодная дымка,
лес — слои деревьев, руины — контуры камня, склеп — арки и приглушённая
бронза, святилище — высокий свет и мягкая симметрия. Нейтральная композиция
не изображает конкретного места. Рисунки не добавляют NPC, проходы,
предметы, опасности или другие игровые сведения.

Изображение появляется без ожидания сети или модели. При ошибке загрузки
сразу показывать встроенную SVG-композицию соответствующего preset.
Подпись располагается на непрозрачной поверхности темы, чтобы контраст
не зависел от картинки. Все SVG без внешних ресурсов, scripts и foreignObject.

## 5. Свет и тема

Декоративные слои находятся за игровыми панелями и в шапке. Они не меняют
цвет текста, фон читаемых поверхностей, цвета состояний успеха/ошибки,
типовые цвета сущностей и токены пакета на `:root`. Применять только локальные
`--tf-scene-glow`, `--tf-scene-glow-opacity`, `--tf-scene-edge`.

| Preset | Цвет света |
|---|---|
| neutral | `#b87333` |
| tavern | `#d59a5c` |
| coast | `#5fae9f` |
| forest | `#76956b` |
| ruins | `#9b917d` |
| crypt | `#8c789a` |
| sanctuary | `#d2bd8c` |

Максимальная непрозрачность света: 0.14 для тёмной темы, 0.06 для светлой.
Night умножает её на 0.75, остальные периоды — на 1. В бою небольшой
локальный край `#c4553f` с непрозрачностью 0.08/0.04; учитывать именно
персональный `scene.mode`, чтобы бой соседней группы не менял оформление.
По умолчанию свет статичен. Переход параметров длится 400 ms;
при `prefers-reduced-motion: reduce` — без перехода. Слои имеют
`pointer-events: none`, не перехватывают прокрутку и не перекрывают модальные окна.

## 6. Контекст хроники

У новых сообщений action/speech/narration сохранять в `Message.data.scene_context`
неизменяемый снимок `{location_id, location_name}`. Передавать его как отдельное
необязательное верхнеуровневое поле `ChatMessage.scene_context`. Оно не заменяет
`data.place`, голоса, броски, пометки ИИ и другие существующие данные.

Для игрока выбирать место автора; для повествования мастера — место фокуса
группы после применения игровых действий. Если у общего повествования нет
одного однозначного места, контекст null. Сохранять снимок перед стримингом,
использовать тот же объект при завершении, повторах описания и восстановлении.
Подготовка, snapshot и чтение истории не создают дополнительных сообщений.
У обычных приветствий до начала истории контекст отсутствует.

Старым сообщениям без контекста не приписывать текущую локацию. Изменение
имени места в мире не переименовывает старые заголовки. Секретные сообщения
не создают общих разделителей.

Добавить необязательное поле `scope: public | party | private` в сообщение
и chunk. Оно задаёт только внешний вид. Канонической границей доступа
остаётся `visible_to`. Истинный whisper и `data.whisper_reply` — private;
ограниченные сообщения с `data.place` — party; остальные ограниченные —
private. При отсутствии scope клиент использует это же консервативное правило.
Контекст приватных сообщений не отображается в хронике.

## 7. Чтение хроники

Перед первым видимым игровым сообщением с контекстом и при изменении
`location_id` появляется компактный разделитель с сохранённым именем.
Повторный вход A → B → A создаёт три раздела; одинаковые соседние ID — один.
Сообщение без контекста разрывает последовательность известных мест:
следующее известное место получает заголовок. OOC, системные записи,
броски и личные шёпоты не создают и не разрывают разделы.

Разделители вычисляются из всей полученной видимой истории до применения
фильтров; фильтры не меняют границы и переносят заголовок к первому оставшемуся
сообщению своего раздела. Для группы мастеру показывать имя места вместе
с отметкой «Группа»; перестановки между группами не склеивать по имени.
Смена scope public ↔ party также начинает раздел, даже при одинаковом ID места.
Ключ заголовка — ID первого игрового сообщения раздела, а не индекс массива.

Повествование: существующий шрифт пакета, 18 px desktop / 17 px phone,
межстрочный интервал 1.65, ширина до 65ch. Действия: компактный блок с именем
героя, одинаковое направление чтения для своих и чужих реплик. Речь:
визуальная цитата. Личные шёпоты сохраняют отдельную рамку и пояснение
видимости; party-повествование оформляется как история с отметкой группы.

Связи `[[id|текст]]` остаются кнопками карточек знаний: обычное тонкое
подчёркивание, более выразительное при hover/focus. Убрать декоративные
надстрочные значки только из повествования через вариант RichText;
остальные использования компонента сохраняют свой вид. Броски, ошибки,
статусы отправки, отмена заявки, голосовые записи, реакции и голосования
остаются доступны. «Только повествование» остаётся отдельным фильтром.

Переоформление, поток и изменение шапки не должны сбрасывать позицию
чтения. При чтении старых записей новые сообщения используют существующую
кнопку «Новые сообщения ↓». При изменении высоты шапки и переносе строк
сохраняется видимое сообщение и его смещение; если игрок был у конца
истории, он остаётся у конца. Для этого достаточно наблюдения размеров
скроллируемого контейнера, без виртуализации ленты.

## 8. Приёмка и границы

Три поставки: (A) данные и шапка; (B) локальный свет; (C) контекст и хроника.
Каждая имеет отдельные проверки и может приниматься независимо.
Обязательны телефон 390×844, узкий телефон 320×568, desktop 1440×900,
светлая/тёмная темы, обе темы пакета, длинное имя, неизвестное место,
сломанное изображение, reduced motion, клавиатура, разделённый отряд,
переподключение и поток → финальное сообщение.

Не включены: портреты, обновление карт, режим скрытия всех панелей,
автоматическое распознавание погоды, генерация изображений, новые
механические эффекты освещения и изменение микшера музыки. Документы
подготавливаются сейчас; реализация начинается после просмотра плана.
