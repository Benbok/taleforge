# Генерация локаций, поставка 1: blueprint, геометрия и переходы

Спецификация: docs/superpowers/specs/2026-10-12-generative-location-maps-design.md (§9, поставка 1).

## Что есть

- **Замысел** (`app/core/layout/intent.py`): части, связи, подходы, полосы рельефа. Команда ведущего
  `prepare_complex` принимает его для места и возвращает квитанцию `location_layout`.
- **Blueprint** (`contracts.py`): участки с локальными координатами и смещением на плане уровня, проходы с двумя
  концами, края открытых участков, рельеф, привязки зацепок и обязательные участки. Хранится в `state.blueprint`
  корня; `state.areas` — реальные id участков; `state.passages` — живое состояние проходов (одно на обе стороны).
- **Провайдер** (`provider.py`): детерминированная раскладка и упрощённая цепочка как fallback; обе проверяются
  `validation.validate`. Не выполнены обязательства — `blocked/layout_unsatisfiable`.
- **Геометрия** (`geometry.py`): эскиз участка кодом — маска пола, твёрдые детали как стены, проходы с клетками,
  края, рельеф, материал. Фаза `location_geometry` заменяет автоматические эскизы, но сохраняет ручные эскизы
  мастера (`manual_preserved`). `MapSketch` несёт маску, края и рельеф (`mask`, `edges`, `terrain`).
- **Маска пола** — общая мера непроходимости шага, пути, прямой видимости и досягаемости (`sketch.solid_cells`).
- **Обстановка** (`furnish.py`): объекты подготовки `location_initial` встают связанными деталями на свободные
  клетки, не у проходов; обстановка ждёт геометрию своего участка. Число проб расстановки ограничено
  (`MAX_TRIES`); не поместившееся попадает в `unplaced`.
- **Переход** (`transit.py`): `begin` → подготовка назначения → `finish` с повторной проверкой. Игрок —
  `map.traverse`; мастер — `traverse_passage` (в ходе — через очередь `scene.state.transits`, до описания).
  Переход соблюдает запреты шага (блокирующие состояния героя) и, для игроков, порядок хода в бою.
  `map.traverse` обрабатывается в фоне: сокет не удерживается, ответ приходит событием `map.traverse.result`.
- **Соседство** (`topology.location_exits`): участки связаны проходами, не вложенностью; тайный проход соседства
  не даёт, пока не раскрыт. Карта игрока перечисляет выходы комплекса только из проходов.

## Чего нет (поставки 2–3)

SVG-слои и узоры, композиция открытых участков на одной карте, память карты по героям (сейчас — `visited_by` и
общий флаг `hidden`), текстовый provider и лимит его вызовов, интеграция с архитектором, подготовка первой сцены и
вперёд, учёт суммарных расходов, дальние ориентиры.

## Решения поставки

- Переход мастера через `move` в участок остаётся (телепорт, падение); правильный путь — `traverse_passage`.
  `move` в участок запрашивает его геометрию, и ход ждёт её до описания.
- Зацепка корня, которой нет в замысле, отдаётся входному участку (не теряется).
- Состояние двери меняет `edit_sketch` с действием open/close/lock/unlock/reveal/hide; удалить или переименовать
  проход нельзя — он общий для двух участков; `sketch_place` поверх эскиза из blueprint запрещён.


## Финальное ревью поставки 1

- Ошибка рассылки не прерывает завершение сохранённого хода. Игрок получает ответ на переход и при неожиданном
  сбое чтения зрителя или первой транзакции; другим сокетам публикуются уже сохранённые изменения.
- Группа хода сохраняется в checkpoint и следует за героями при описании. Переход с панели заканчивается в фоне
  и восстанавливается после перезапуска без running MasterTurn.
- Перемещение, удаление перехода из очереди и его событие в checkpoint фиксируются атомарно. Конфликт мира
  оставляет ход в preparing для повторного завершения; панель обрабатывает только собственную очередь.
- Ожидание подготовки и рассылка свежей проекции проходят без открытой транзакции БД.
- Подходы между комплексами работают в обе стороны, включая внешний endpoint на участке другого комплекса.
  При неоднозначной локальной ссылке прохода сервер отказывает; скрытые проходы её не раскрывают.
- Blueprint разбирается один раз на корень при построении карты; JSON seed ограничен int32, бесконечные числа
  дают LayoutError, отрезки краёв проверяются на длину и начало.
- Типы web API обновлены. Новый map.traverse.result зарегистрирован в перечне событий; интерфейс выбора
  прохода на карте относится к поставке 2.

Решения по каждой строке minor (deferred) приведены ниже; существенные дефекты завершения хода,
восстановления, ответа игроку и транзакций устранены. Дополнительные редкие ветки геометрии/provider и
коллизии длинных идентификаторов остаются отдельными улучшениями; PostgreSQL требует своего тестового окружения.

2026-10-12 пользователь выбрал слияние в main с разрешением конфликтов. Слияние выполнено в отдельном
worktree main: основная копия находится на feat/narrative-adaptation с незакоммиченными изменениями и не
переключалась. Текущий main объединился без конфликтов, включая app/gateway/protocol.py.
После проверки объединённого результата журнал SDD удаляется; worktree сохраняется до отдельного согласия.
