# Архитектура входа универсального мастера

Изменения относятся к универсальному движку. Авторитетные данные хода строит
`prompting/context.py::build_decide_context`; модель получает их через
`prompting/messages.py::decide_messages`. Нарезка происходит при сборке сообщения:
полный контекст сохраняется для компилятора, проверки доказательств и дозагрузки лора.

## Постоянная и переменная части

Сначала идут ядро и выбранные модули правил, затем неизменный список возможностей
движка. Схема `IntentV2` передаётся инструментом `submit_action`. Пользовательское
сообщение содержит переменные данные; поле `repair` всегда последнее.
Для одинакового набора модулей системная часть байт-в-байт одинакова.

`cacheable` добавляет явный маркер только моделям `anthropic/*` и `claude*`.
DeepSeek использует собственный кэш префикса без этой разметки. Количество
прочитанных из кэша токенов берётся из ответа провайдера; отсутствие метрики
не означает ноль. Счётчик `request_size` считает символы, а не токены.

## Добавление правила

1. Определить, требует ли правило понимания смысла. Проверяемые ограничения
   добавить в схему или серверный валидатор с понятным сообщением об исправлении.
2. Написать тест нарушения и увидеть его падение, затем реализовать проверку.
3. Семантическое правило поместить в `CORE` либо один из `PromptModule` в
   `prompting/modules.py`: travel, objects, magic, speech, combat, rewards.
4. Для нового условия проверить пустое и неизвестное состояние. Неизвестное
   состояние включает модуль. Явная атака включает combat даже без врагов;
   действующие эффекты сохраняют magic для их снятия или продолжения.
5. Обновить `docs/prompt-rules.md` и тест покрытия исходных предложений,
   добавить типовую реплику и снять сравнимый замер.

Судить о допустимости действия по ключевым словам нельзя. Лексический поиск
решает только, какой контекст передать модели; окончательное суждение о мире
остаётся за моделью и проверкой смысла.

## Добавление контекста

Добавить полное поле в `build_decide_context` и его представление в
`prompting/slicers.py`. Сцена, доступные выходы, ресурсы, ограничения и действующие
эффекты сохраняются. Описания неназванных предметов обрезаются до первой строки;
механические поля предметов остаются целыми. Карточка героя сокращается, история
содержит последние шесть реплик до 400 символов каждая.

Лор разбивается по абзацам из laws, powers, world, inhabitants, history.
ID имеет вид `laws:0`, порядок полей и абзацев фиксирован. Это адреса внутри
снимка мира, а не постоянные идентификаторы после редактирования авторского текста.
Совпадение нормализованных основ русских слов определяет порядок блоков;
подробности укладываются в бюджет 1500 символов. Указатель всех блоков остаётся
доступен даже при нулевом совпадении. Не добавляйте копии полного лора в соседние
поля: студийные laws/powers/world также убираются из переменной части.

Если подробностей не хватает, модель возвращает `need_lore` с максимум четырьмя
известными ID. Сервер сохраняет запрос в `MasterTurn.trace.requested_lore`,
добавляет полные блоки сверх исходного бюджета и использует оставшуюся попытку.
Общий предел — два вызова разбора, включая восстановление после сбоя. Неизвестные
ID игнорируются; повторная просьба после исчерпания бюджета не выполняет частичный
замысел. `need_lore` не попадает в исполняемые операции или сохранённую способность.

Проверка смысла получает такое же представление лора и нарезанные доказательства.
Нормативные laws, powers и world передаются ей полностью сверх лексического
бюджета: запрет в конце длинного абзаца не должен исчезать за краткой сводкой.
Рассказчик получает только уже отфильтрованный по аудитории публичный контекст:
исходы, сцену и общие знания. Частный указатель лора туда не добавляется.
Нарезка истории не удаляет `scene_note` и не меняет сохранённые исходы.

## Проверка качества и расширение набора

`tests/eval/cases.py` содержит двадцать реплик двух миров. Для нового случая
указать фикстуру, source и структурные ожидания в `Expect`; добавить проверку
самого ожидания в `test_eval_checks.py`. Реальные вызовы отделены от pytest:

```powershell
python -m tests.eval.run --n 5 --output tests/eval/new-result.json
```

Прогон платный и отправляет фикстуры провайдеру. Снимок тестового Шира и станция
разрешены владельцем для DeepSeek Flash. Замена данных или провайдера требует
соответствующего разрешения. Сравнивать нужно одинаковые фикстуры, случаи,
повторы и модель. Изменение набора означает новую базу, а не улучшение старого
результата. Старые отчёты не перезаписываются.

Первоначальная база `baseline-original.json` до оптимизаций: 70/100 успешных ответов. Итоговый отдельный
замер: 74/100; средний вход 9041 вместо 11925 токенов, сокращение около 24%.
Промежуточные результаты и размеры по частям сохранены в `tests/eval/*-result.json`.
Желаемые 50% экономии не достигнуты: ради этой цифры контекст дополнительно не удалялся.

Это небольшая стохастическая выборка, без доказательства статистического превосходства.
Набор проверяет ответ разбора и дозагрузку лора, но не серверный repair, весь цикл
проверки смысла или литературное качество. Эти части покрываются интеграционными
тестами и отдельной проверкой в живой кампании. Обычный осмотр по-прежнему часто
получает от модели `check`; серверная нормализация исправляет безопасные случаи.

## Проверка в игре и независимый обзор

Образ приложения пересобран и перезапущен. В тестовой кампании через штатный
WebSocket прошли речь с хозяином (`speak`), снятие лука (`unequip`) и переход
в соседнее место (`move`); все три хода завершены с сохранённым рассказом.
При переходе проверка смысла отклонила ошибочный осмотр, повторный разбор
сохранил требуемый переход. Фактические результаты — `tests/eval/manual-result.json`.

Независимый обзор выявил два важных случая, оба исправлены с тестами RED→GREEN:
нормативный запрет за пределами сводки и бюджета; восстановление после последнего
запроса лора. Нормативные блоки теперь целиком доступны проверке смысла.
Исчерпанный запрос лора атомарно сохраняется с terminal failure; восстановление
не выполняет запасное действие и не получает дополнительную попытку модели.

Отложенное небольшое замечание: вручную сформированные служебные снимки с
неверными типами, например `history: null`, пока требуют нормализации вызывающей
стороной. Рабочий `build_decide_context` формирует корректные списки и строки;
пустые миры с корректными пустыми значениями покрыты тестами.
