# Генерация исследуемых сцен — поставка 4: сюжетные резервы

**Спецификация:** [2026-10-11-explorable-scene-generation-design.md](superpowers/specs/2026-10-11-explorable-scene-generation-design.md), редакция 2, §4.4, §4.5, §8.1, §10.
**Объём:** только поставка 4. Подготовка остаётся детерминированной (LLM — поставка 5), интерфейс и явное
включение — поставка 6.

## 1. Что было

- Зацепки каркаса — текст: `reveals[].clues[] = {at, text}`, без id. Индекс в массиве меняется при пересмотре.
- `PlotAnchorBinding` объявлен в ORM, но ничего его не создаёт. Поставка 3 переводит подготовку места
  с зарезервированной зацепкой в `blocked/plot_conflict`.

## 2. Решения

### 2.1. Стабильные id и физический носитель

- У зацепки появляются необязательные поля `id` и `carrier`. Сервер выдаёт `id` (`clue_<8 hex>`) каждой зацепке
  без него при проверке нового каркаса и пересмотра; дальше id хранится и не пересчитывается. `render` показывает id,
  чтобы пересмотр мог сохранить зацепку; повтор id — ошибка проверки.
- `carrier = {name, description, template_id?, hidden?}` — физическая вещь, через которую зацепку находят
  (письмо, дневник, перстень). Только зацепки с `carrier` получают привязку: зацепка-разговор или наблюдение
  остаётся текстом, филлер обязательств не получает. Без `template_id` носитель — новый шаблон пакета
  `item.plot_note` («Записка»: без цены, не случайная добыча).
- Старые каркасы без `carrier` привязок не получают (§8.1: не по догадке). Явный адаптер — команда ведущего
  `bind_plot_anchor(anchor_id, entity_id)`: существующий предмет становится носителем без копирования.

### 2.2. Привязки (`app/core/plot_anchors.py`)

`sync_bindings` вызывается при каждой записи каркаса (принятие, новый вариант, пересмотр, инструменты мастера,
правка владельцем) и сверяет привязки с каркасом:

- новая зацепка с носителем — `reserved`; цель — сущность места каркаса (`at` → `entity_id` после `develop`),
  до разворота места цели нет и размещать нечего;
- `reserved` — снимок (текст, носитель) и цель обновляются: факт ещё не создан;
- `materialized` и `revealed` не меняются: пересмотр не переписывает созданный факт;
- зацепки больше нет в каркасе, привязка `reserved` — `replaced_by_story`;
- носитель удалён (`holder_entity_id` обнулён внешним ключом) — `lost`; генератор его не восстанавливает;
- тайна раскрыта (`plot_reveal`) — созданные носители её зацепок получают `revealed`.

### 2.3. Носители в подготовке

- Резерв корня места фиксирует носители всех `reserved` привязок цели: `anchors = [{anchor_id, binding_id, carrier,
  cost}]`. Стоимость учитывается до случайных находок, как авторская добыча: `item.plot_note` и носитель без
  механики — 0, шаблон из профиля — его `generation_cost`, иначе стоимость неизвестна и случайный остаток
  обнуляется с диагностикой. Обязательный носитель не отбрасывается из-за бюджета или лимитов.
- План ставит видимый носитель отдельным слотом `anchor:<id>`. Скрытый (`hidden`) policy кладёт в один из
  выбранных контейнеров отдельным генератором (`seed` + id зацепки): добыча от этого не меняется. Носитель
  попадает в резерв этого контейнера и создаётся при его исследовании. Нет контейнеров — носитель на виду,
  с диагностикой.
- Предложение обязано заполнить слоты носителей; имя носителя — факт сюжета и не меняется.
- Финальная транзакция перепроверяет каждую привязку: она всё ещё `reserved` за этой целью — носитель
  создаётся уникальным предметом с `plot_anchor`, привязка `materialized`; иначе (пересмотр, раскрыто,
  перенесено) — пропуск с диагностикой в manifest, бюджет не перераспределяется. Носитель создаётся по
  текущему снимку привязки.
- Привязка, появившаяся после резерва корня (поздняя): при подготовке корня ставится на виду, вне бюджета,
  с диагностикой `late_anchor`; если место уже готово — создаётся при следующем входе героев (`move`) в той же
  транзакции. Блокировка `plot_conflict` из поставки 3 снимается.
- Вход в место с `reserved` привязками без флага `scene_generation` всё равно резервирует корень, но с профилем
  `minimal`: случайной добычи нет, обязательства выполняются (§4.1).

## 3. Проверки

- id выдаются один раз, переживают пересмотр; повтор id — ошибка; зацепка без носителя привязки не получает;
- носитель на виду создаётся при подготовке, скрытый — при исследовании контейнера, ровно один раз;
- носитель учитывается в бюджете до добычи, добыча и seed контейнеров от него не меняются;
- пересмотр меняет текст `reserved` носителя, но не созданного; удалённая зацепка — `replaced_by_story`;
- удалённый носитель — `lost`, повторная подготовка его не создаёт;
- существующий предмет становится носителем без копии; поздняя привязка к готовому месту создаётся при входе;
- без флага генерации вход в место с зацепкой создаёт только носитель;
- зацепка переживает fallback: детерминированный provider создаёт носитель.

Также полный серверный набор, контракт, сборка и тесты клиента, `ruff`, проверка пакета.

как раньше.
