# Taleforge — World Objects: этап 0. Проверки, риски и план PR

**База:** `main` @ `7f8baf9ffa39c1ffa038a662b945848455859b2d`.  
**Назначение:** критерии приёмки проекта [схемы и контрактов](world-objects-stage0.md), программа регрессионных испытаний и последовательные границы изменений.  
**Важно:** тесты и изменения ниже — *предлагаемые*, а не выполненные. Этап 0 документационный.

## 1. Предварительные факты и риски

| Приоритет | Факт из текущего кода | Риск | Требуемая проверка |
| --- | --- | --- | --- |
| P0 | `pick_up_item` удаляет `Entity` после полного подбора | Теряется id и история уникального предмета | Сохранение id после pickup/drop/pass |
| P0 | `_put_in_scene` объединяет совпавшие шаблон/имя/позицию | Два уникальных предмета сольются | Стак только при явной совместимости |
| P0 | `in_scene_entities` без известных мест возвращает все `Entity`, кроме `location` | Переносимый уникальный предмет в инвентаре может ошибочно выглядеть как предмет сцены | Нет утечек `location_id=null` |
| P0 | `pick_up_item` проверяет присутствие в комнате, но не `container_id` | Можно забрать вещь из закрытого сундука напрямую по id | Доступность по цепочке родителей |
| P0 | `party_map` показывает предметы по `location_id` | Вложенное скрытое содержимое появится на карте | Проекция исключает вложенные/скрытые сущности |
| P0 | `sketch.features` не содержит ссылки на `Entity` | Рисуется два одинаковых шкафа | Один маркер и одно состояние |
| P0 | `enter_room` может заранее создать соседние комнаты | Генерация до реального входа и спойлеры | Подготовка привязана к фактическому входу |
| P0 | `adventure.room_text` содержит `encounters` как сценарный текст | Противники «остаются» на карте после других решений | Токены только по актуальному состоянию и правилам встречи |
| P0 | `plot.reveals[].clues[]` без постоянных id | При `merge_revision` связь с дневником может «съехать» | Устойчивые id и snapshot |
| P0 | `sketch_place` способен заменить целый эскиз; `surveyor` проверяет `layout_rev` | Устаревшая модель перезапишет правки ведущего | CAS по ревизии и запрет наложения |
| P1 | Каталог показывает `proposal` только в тестовом режиме | Недоступные таблицы попадут в обычную кампанию | Совместимость `canon/proposal` |
| P1 | `loot_table` содержит `by_scenario`, `npc`, `lead_item_ref` и прочие специальные строки | Таблица ошибочно трактуется как список предметов | Отбор только поддерживаемых вариантов |
| P1 | Система событий ведёт обратные дельты и savepoint | Откат новой операции может оставить запись генерации | Атомарная фиксация и inverse |
| P1 | Игровые кампании могут делить один сервер и разделять отряд | Cross-campaign или cross-character утечки | Проверки `campaign_id` и viewer |
| P1 | Схема карты и WebSocket имеют контракт | Новый ответ сломает клиент | Проверки `app.contract` и TS |

## 2. Матрица обязательных сценариев

### 2.1. Данные и перенос (OBJ)

| ID | Сценарий | Ожидаемое поведение |
| --- | --- | --- |
| OBJ-01 | Старый обычный предмет: `place_item → pick_up_item → drop_item` | Нынешний предмет и `qty` продолжают работать |
| OBJ-02 | Создано два одинаковых уникальных меча | Разные `Entity.id` и `world_entity_id`, без слияния |
| OBJ-03 | Уникальный предмет прошёл `pickup → pass → drop → pickup` | Один исходный id, один владелец, одна история |
| OBJ-04 | Уникальная вещь полностью подбирается | `Entity` не удаляется; `location_id = null` в инвентаре |
| OBJ-05 | Разделение стака обычных стрел на части | Сумма количества сохраняется |
| OBJ-06 | Повторная передача с одним `call_key` | Успех возвращён идемпотентно, перемещения дважды нет |
| OBJ-07 | Попытка перенести предмет из другой кампании | Отказ, данные не меняются |
| OBJ-08 | Попытка вложить контейнер внутрь самого себя или его потомка | Отказ до изменения состояния |
| OBJ-09 | Вложенный предмет внутри сундука с `location_id` текущей комнаты | На полу/`around` не появляется |
| OBJ-10 | Уникальная вещь в инвентаре при отсутствии активной сцены | Не появляется в `in_scene_entities` |
| OBJ-11 | Уничтожена уникальная вещь | История/id сохраняются; не отображается и не выдается повторно |
| OBJ-12 | Исходный шаблон скрыт или больше недоступен | Корректная ошибка/совместимый снимок, не замена выдуманной механикой |

### 2.2. Контейнеры (CNT)

| ID | Сценарий | Ожидаемое поведение |
| --- | --- | --- |
| CNT-01 | Сундук создан, закрыт, предмет вложен | Предмет не виден и не подбираем без доступа |
| CNT-02 | Игрок открывает сундук | Состояние физически изменено для всех |
| CNT-03 | Первый обыск вызывает материализацию обычной мелочи | Один зафиксированный результат |
| CNT-04 | Повторный обыск уже `resolved` | Новые предметы не появляются |
| CNT-05 | Пустой контейнер успешно обработан | `ready` + пустой список, не ошибка |
| CNT-06 | Два игрока параллельно открывают один сундук | Одна materialization, остальные читают её |
| CNT-07 | Сундук разрушают до первого открытия | Сначала содержимое, затем механические последствия |
| CNT-08 | Сундук перенесли в другую комнату | `location_id` всех вложенных предметов согласован |
| CNT-09 | Герой видит сундук, но не тайник | Никакой информации о тайнике в ответе игроку |
| CNT-10 | Добычу из сундука забрали | Сундук остаётся `resolved`, новый дроп не создаётся |
| CNT-11 | Уникальная сюжетная зацепка зарезервирована в сундуке | Бросок редкости не удаляет её |
| CNT-12 | Невозможное действие (открыть разрушенное/достать сквозь замок) | Предсказуемый отказ без записи частичного изменения |

### 2.3. Локации, геометрия и встречи (LOC/MAP)

| ID | Сценарий | Ожидаемое поведение |
| --- | --- | --- |
| LOC-01 | Два героя одновременно впервые входят в комнату | Один результат подготовки |
| LOC-02 | Создана соседняя комната-навигатор книги | Не подготовлена до входа |
| LOC-03 | Новая пустая комната | Валидное `ready` без объектов |
| LOC-04 | Герои покидают и возвращаются | Все изменения сохраняются |
| LOC-05 | Техническая модель не ответила | Нет частичного содержимого; резервный сценарий или `blocked` |
| LOC-06 | Ответ LLM устарел после правки ведущего | Результат отклонён, правка не потеряна |
| LOC-07 | Автоматическая генерация отключена в существующей кампании | Вещи остаются, генерация не запускается |
| LOC-08 | Старое сохранение с посещённой комнатой | `legacy_preserved`, перегенерации нет |
| MAP-01 | `Entity` связан со `sketch.feature` | Один видимый объект/маркер |
| MAP-02 | Несвязанный `feature` — декорация | Не создаёт переносимый `Entity` |
| MAP-03 | Интерактивный `Entity` отсутствует в `features` | Отображается по существующей сценной проекции |
| MAP-04 | Мастер переместил шкаф | Объект/маркер синхронизированы |
| MAP-05 | Готовая комната с `encounters`, но без созданных врагов | Никаких лишних токенов |
| MAP-06 | Противник погиб и удалён/остался мёртвым | Нет повторного спавна из описания |
| MAP-07 | Настройка сложности встречи | Существующий механизм сложности, без вмешательства генератора предметов |
| MAP-08 | Динамический токен скрыт, а враг нарисован на фоне | Проблема фонового изображения отдельно зафиксирована, без ложноположительного теста |

### 2.4. Сюжет, доступ и контент (PLOT/SEC)

| ID | Сценарий | Ожидаемое поведение |
| --- | --- | --- |
| PLOT-01 | Тайна имеет 3 зацепки в 2 разных источниках | Ограничение сохранено |
| PLOT-02 | Нераскрытая зацепка связана с существующим дневником | Материализация не создаёт новую копию |

| PLOT-04 | Архитектор пересмотрел будущий акт | Материализованные объекты не изменены |

| SEC-01 | Скрытый контейнер в комнате двух героев | Только имеющий право знания игрок получает детали |
| SEC-02 | `map.get` от другого участника кампании | Нет данных чужой кампании |
| SEC-03 | Игрок знает предмет, но не его свойства | Имя/описание по уровню знания, скрытая механика не раскрывается |
| SEC-04 | Техническая модель предложила несуществующий `item_template` | Отказ с диагностикой |

| SEC-06 | Описание предмета содержит текст-команду модели | Рассматривается как недоверенное содержимое |

### 2.5. Атомарность и стабильность (TX/OPS)

| ID | Сценарий | Ожидаемое поведение |
| --- | --- | --- |
| TX-01 | Сбой после вставки половины объектов | В БД нет частично созданной сцены |
| TX-02 | Два исполнителя с одним target/phase | Не более одного `ready` и одного набора содержимого |
| TX-03 | Просроченный lease пытается сохранить данные | Отказ |
| TX-04 | Повтор websocket/tool после таймаута | Операция не дублируется |
| TX-05 | Возникла ошибка после изменения инвентаря и до изменения контейнера | Транзакция откатывает обе стороны |
| TX-06 | Перезапуск приложения посередине подготовки | Lease восстанавливается/истекает; нет частичного содержимого |
| TX-07 | Нулевое количество или несовместимый `qty` | Валидатор отклоняет |
| OPS-01 | Карта открыта долгое время | Чтения не вызывают новую LLM-генерацию |
| OPS-02 | Повторное посещение 10 раз | Никаких дополнительных расходов генератора |
| OPS-03 | Запуск без подключённой технической модели | Резервный путь не ломает геймплей |
| OPS-04 | Перезапуск backend с туннелем | Состояние устойчиво и одинаково для игроков |

- `cd web && npm run gen:api`
- `cd web && npm run build`

- [x] Есть безопасная legacy-политика.
