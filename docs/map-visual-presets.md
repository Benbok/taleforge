# Визуальные пресеты карты Taleforge (2D)

## Назначение и границы

- **Источник истины игрового мира:** `Entity`, `Entity.state` и существующий зрительский `scene_view`.
- **Внешний вид:** только на клиенте. Не влияет на обнаружение, редкость, возможность подобрать предмет, боевые правила и положение клетки.
- **Базовый стиль:** небольшие векторные SVG-пиктограммы. Один общий рендерер `Token` для вкладок «Вокруг» и «Карта книги»; двери и неподвижные детали эскиза используют тот же `MapGlyph`.
- **Без внешней загрузки ассетов:** никакого сетевого обращения, случайной генерации изображений, эмодзи или шрифтовых значков на самих токенах.

## Контракт

В `Entity.state` допускается необязательное поле `visual_key` — стабильный ключ из каталога `VISUAL_VARIANTS`.

Пример:

```json
{
  "visual_key": "item:chest",
  "cell": [1, 2]
}
```

Это **не новый тип сущности**: `Entity.kind` и результат `entity_type(e)` остаются прежними. В `app/core/map.py` визуальный ключ проходит тем же зрительским фильтром, что и сама сущность, затем попадает в `around` и `scene_view`; `adventure.book_map()` передаёт его токену карты книги.

Клиент всегда резолвит `entityVisual(type, key)`. Если ключ неизвестен, пуст, относится к другой категории или совпадает с унаследованным свойством JS-объекта, используется базовый пресет соответствующего типа, без вывода непроверенного текста и без запроса внешних картинок.

## Как добавлять предметы

1. Добавить новое устойчивое имя, например `item:lantern`, в `VISUAL_VARIANTS` (`mapPresets.ts`) с указанием семейства `item`, глифа, читаемой подписи, формы и CSS-цвета.
2. Если имеющихся пиктограмм недостаточно, добавить **одну** векторную пиктограмму в `MAP_GLYPHS` (`MapGlyph.tsx`) в координатах `24×24`, без внешних ассетов.
3. При создании экземпляра предмета из шаблона сохранять `visual_key` в `Entity.state`. Позднее это можно делать в существующем процессе формирования объектов и каталога предметов; карта при этом не изменяется.
4. Дополнить тесты `mapPresets.test.ts` и проверить оба представления. Не писать условные проверки по русскому названию, ID сущности или месту появления.

Категории по умолчанию: `hero`, `creature`, `npc`, `item`, `landmark`, `location`, `lore`. Для дверей и деталей комнат предусмотрены собственные специализированные реестры `EXIT_VISUALS` и `FEATURE_VISUALS`; они не подменяют физическую топологию карты.

## Интеграция с item_template и материализацией предметов

В `item_template` допускается необязательное поле `visual_key: item:potion` (либо иной ключ семейства
`item:...`). Валидация пакета проверяет тип и префикс, а конкретный рисунок выбирает **только**
`entityVisual("item", visual_key)`. Это не новая игровая характеристика, не основание для механики и не
новая система иконок.

Существующая `app/tools/master/items.py::_put_in_scene` копирует ключ из `CatalogView` в
`Entity.state.visual_key` при `place_item` и `drop_item` (то есть также после
`give_item → drop_item` и `pick_up_item → drop_item`).
При объединении с существующей стопкой новый ключ заполняет лишь **отсутствующее** поле, не меняя
вручную выставленный визуальный вариант. `InventoryItem` не требует отдельного поля визуала или создания
`Entity` на каждую строку инвентаря.

Если у шаблона нет `visual_key` или вариант неизвестен клиенту, работает стандартный `MAP_PRESETS.item`.
Для наполнения каталога достаточно пометить уже существующий `item_template` ключом из
`VISUAL_VARIANTS`; переименование предметов и локализация на выбор значка не влияют.

Сопутствующие правки исходных YAML — новые версии контент-пакетов: при уже импортированной версии
нельзя менять файлы с прежним номером (контрольная сумма импортера). Уже размещённые в старых кампаниях
предметы с отсутствующим ключом остаются допустимыми; отображение не требует миграций.

Для будущего World Objects / генератора использовать те же данные `item_template → _put_in_scene →
Entity.state.visual_key` и `sketch` как отдельную геометрию. Не разрабатывать второй реестр SVG,
новый рисунок по каждому LLM-запросу или логику визуала в `MapWindow` / `BookMap`.

## Состояния и доступность

Рендерер `Token` отдельно принимает `selected`, `ring`, `faded`, `dashed`, `badge` и `label`. Это не часть имени пресета: один сундук остаётся сундуком вне зависимости от выделения или доступности. Категории различаются также силуэтом и рисунком, а не одним цветом. Цвета определяются переменными темы Taleforge, поэтому используются и в светлой, и в тёмной теме.

Для будущих изображений (иллюстраций предметов) реестр можно расширить полем описания ассета и resolver'ом с проверенными ресурсами. Нельзя передавать произвольный URL из состояния мира прямо в SVG: сначала нужен каталог доверенных идентификаторов и fallback. Текущий PR такого функционала не добавляет.
